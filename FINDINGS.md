# FINDINGS.md — Launch-readiness audit (read-only), 2026-09-05

## Repo map

One npm package (`package.json` name `builder`, private, v0.0.0) containing both halves of the product:

- **Admin SPA** — Vue 3 + Vite (`src/`), built to `dist/`, served under `/admin/` (Vite `base: '/admin/'`). Entry `index.html` → `src/main.ts` → router (`src/router/index.ts`: build, preview, login, setup, invite). State is composable singletons (`src/composables/`); the document model and DSL live in `src/lib/` (parser `syntax.ts`, reconcile, merge, styles). `src/lib/shared/*.js` is plain-JS logic shared with the server exporter.
- **Node server** — `server/index.mjs` (no framework, no Express): auth (`auth.mjs`, scrypt + HttpOnly `sb_session` cookie), a key-value store API over flat JSON files (`server/data/store/`), media library (`media.mjs`, sharp), publish/export API, and static serving of both the built SPA (`dist/` at `/admin`) and the exported site (`server/data/site/` at `/`).
- **Data flow**: user authors pages in a DSL in the SPA → autosave PUTs the whole project JSON to `/api/store/superbird-project:<branch>` → publish (`POST /api/published`) snapshots it and runs `server/export.mjs`, a pure-JS re-implementation of the client renderer (`useRenderNode.ts`) that emits static HTML + Tailwind CSS (`@tailwindcss/node`) + a ~1.5 KB runtime (`site-runtime.js`) into `server/data/site/`, optionally zipped (`zip.mjs`) or pushed to GitHub (`github.mjs`). Media data-URLs are interned to hashed files by `export-media.mjs`.
- **Scripts/tests**: `npm run build` (vue-tsc + vite, **passes**), `npm run serve`, `npm run test:e2e` (one Playwright smoke test, **currently fails** — see C1), `scripts/generate-demo.ts` (generates `public/demo-project.json`, the "Brume" demo).
- **Naming state**: repo dir "superbird", package "builder", storage keys/filenames "superbird-*", one audit note says "fabrica", and the planned npm name "guano" appears **nowhere** in the repo — the rename and all npm packaging work have not started.

Verification runs: `npm run build` ✅ exit 0; `npm run test:e2e` ❌ 1/1 failed (stale selector, C1); `npm pack --dry-run` → 197 files, 308 kB (contents analyzed in P-findings).

## 2. Security

Threat model: authed admin SPA (roles admin/editor/contributor; contributor semi-trusted) + public published static site on the **same origin** as `/api` and `/admin`; user content compiled to HTML by `server/export.mjs`.

- **S1 · CRITICAL · `server/export-media.mjs:17,59-71` + `server/index.mjs:714-728`** — Data-URL SVGs in project content (`node.src`, `background`, `conditions.swapSrc`, collection image fields — all contributor-writable via `PUT /api/store`) are written to `assets/media/<hash>.svg` verbatim with **no `sanitizeSvg` call** (unlike the upload path, `server/media.mjs:281`), and `handleStatic` serves them as `image/svg+xml` with no CSP (unlike `/media/:id`, which sends `default-src 'none'`, `media.mjs:520`), so a contributor gets stored XSS on the published origin — same origin as the admin session cookie. Fix: run `sanitizeSvg` on interned `image/svg+xml` payloads in `export-media.mjs` and serve static `.svg` with `Content-Security-Policy: default-src 'none'`.
- **S2 · HIGH · `server/index.mjs:465-468`** — `DELETE /api/store/:key` has no contributor gate (the PUT branch at 458-461 does), so a contributor can delete `superbird-project:main` and destroy the entire project. Fix: mirror the contributor rejection (or forbid contributor DELETE of project keys outright).
- **S3 · MED · `src/lib/shared/background.js:38-42` via `server/export.mjs:444-453,249`** — Background URLs are interpolated unquoted into `background-image:url(${url})`; `escapeHtml` doesn't touch `)` or `;`, so a crafted `node.background` injects extra inline-style declarations (full-viewport overlay/clickjacking, request exfil via `url()`). Fix: reject or CSS-escape URLs containing `)`, quotes, or whitespace.
- **S4 · MED · `server/index.mjs:437-451`** — `GET /api/store` returns the full project blob to any authenticated role, so contributors can read `settings.smtp` credentials they're forbidden to modify. Fix: redact secret fields for contributors or move SMTP config server-side like the GitHub token.
- **S5 · MED · `server/media.mjs:433,479-488`** — Media replace and delete are open to contributors, letting a semi-trusted user overwrite or remove any asset used across the site. Fix: gate replace/delete behind editor+ or ownership.
- **S6 · MED · `server/index.mjs:558-560` + `server/util.mjs:24-29`** — The GitHub token is stored plaintext in `publish.json`, and `writeAtomic` never sets a restrictive mode, so all data files (users, sessions, invites, token) are world-readable under default umask on a shared host. Fix: write data files with `mode: 0o600` (dir `0o700`).
- **S7 · MED · `server/index.mjs:615-619` + `server/zip.mjs:154-159`** — Project import reads up to 512 MB and inflates entries with no cumulative decompressed-size ceiling → zip-bomb memory exhaustion (admin-only, still a one-click DoS). Fix: cap total `uncompSize` before inflating.
- **S8 · MED · `server/auth.mjs:141-149,193-198`** — Password change does not invalidate the user's other sessions; a stolen 30-day session survives a reset. Fix: destroy other sessions on password change.
- **S9 · MED · `server/auth.mjs:392-401`, `server/index.mjs:202`** — Rate limiting keys on `req.socket.remoteAddress`; behind any reverse proxy (the typical deploy) all clients share the proxy's IP, so the brute-force control both mis-fires and stops identifying attackers. Fix: honor a trusted `X-Forwarded-For` behind an opt-in flag.
- **S10 · MED · `server/index.mjs:690-693,697-709,714-728`** — Neither the admin SPA nor the published site sends `Content-Security-Policy` or `X-Frame-Options` (only `nosniff`), leaving both framable and giving any XSS free rein. Fix: add CSP + `frame-ancestors`/XFO to both static handlers.
- **S11 · LOW · `server/auth.mjs:392-397`** — 10 failed logins lock a targeted account's email for 15 min → trivial user-lockout DoS. Fix: soft delays / per-IP emphasis instead of a hard per-email lock.
- **S12 · LOW · `server/auth.mjs:239-248`** — Cookie `Secure` flag only with `NODE_ENV=production` or `COOKIE_SECURE=1`; a non-technical self-hoster behind TLS gets a non-Secure session cookie by default. Fix: default Secure on (or detect `X-Forwarded-Proto`).
- **S13 · LOW · `server/github.mjs:22,55-96`** — Repo/branch regexes allow `.`/`..` segments, permitting api.github.com path manipulation under the configured token. Fix: reject `..` and edge dots.
- **S14 · LOW · `server/index.mjs:283-284`** — `/api/users/members` exposes all member names/emails (and invite emails) to contributors. Fix: limit PII to editor+.
- **S15 · LOW · `server/export.mjs:476-479`** — `favicon`/`og:image` are the only URL sinks not passed through `SAFE_SRC` (inert today, but the `data:image/svg+xml` case feeds S1). Fix: apply `SAFE_SRC`.
- **S16 · LOW · `server/export.mjs:466,477,480`** — `settings.domain` is interpolated into canonical/OG URLs unvalidated (poisoning only). Fix: hostname-pattern check.
- **Verified strong** (for the record): store keys, media ids, static paths, and zip entries are all traversal-proof (`STORE_KEY_RE` index.mjs:357, `ID_RE` media.mjs:32, `startsWith(DIST/SITE)` index.mjs:698-716, `safeName` zip.mjs:29-34); CSRF is covered by `SameSite=Lax` + an Origin check on every mutating request (index.mjs:738-740, media.mjs:72-80); passwords are scrypt, sessions/invites stored as sha256, `PUBLISH_TOKEN` compared timing-safe; upload validation includes magic bytes, size caps, and a pixel-bomb guard; and the exporter's HTML escaping is comprehensive — rich text is allowlist-sanitized (`richtext.js`), hrefs/srcs scheme-checked, JSON blobs `</`-escaped, fonts regex-gated. The XSS surface is essentially the two gaps above (S1, S3).

## 3. Packaging & distribution readiness

- **P1 · CRITICAL · `package.json:1-5`** — The stated launch plan (npm `guano` package + CLI + `create-guano` scaffolder) has no corresponding code: the package is `"name": "builder"`, `"private": true`, `0.0.0`, with no `bin`, no `files`, no CLI entry, no scaffolder, no workspace, and zero "guano" references repo-wide. Fix: this is a project to build, not a bug to patch — rename, add a `bin` that boots `server/index.mjs`, a `files` allowlist, and a `create-guano` scaffolder before any launch date is set.
- **P2 · HIGH · `npm pack --dry-run` (197 files) vs `.gitignore:42`** — With no `files` field the tarball ships `.claude/settings.local.json` (local permission history with personal absolute paths), `CLAUDE.md`, `QUESTIONS.md` (a security-findings doc), `notes/fabrica-audit.md`, `e2e/`, `scripts/`, and all of `src/` — while **omitting `dist/`** (gitignored), so an installed tarball has no SPA to serve at `/admin` and cannot run. Fix: add `files: ["dist", "server", "package.json", …]` and a `prepack` build.
- **P3 · HIGH · `server/index.mjs:62,66`** — `DATA_DIR` defaults to `<package>/server/data` (resolved from `import.meta.url`), which for an npm-installed package means writing user data, sessions, and the site inside `node_modules` (wiped on reinstall). Fix: default the data dir to `process.cwd()` (e.g. `./guano-data`) when not overridden by `SB_DATA_DIR`.
- **P4 · MED · repo root** — No `LICENSE` file and no `license` field in package.json; unpublishable and legally unusable as-is. Fix: pick a license, add both.
- **P5 · LOW · `package.json:16-24`** — `@tailwindcss/vite` is build-only (`vite.config.ts:6`) but sits in `dependencies`. Fix: move to devDependencies (note the inverse is handled correctly: `sharp` and `@tailwindcss/node` are genuine server-runtime deps).
- **P-ok** — `engines` is declared; all server paths resolve from the module location, not cwd guesses, so the layout survives installation *if* `dist/` ships (P2).

## Top 5 before launch

1. **S1 — sanitize interned SVGs + CSP on served media** (stored XSS on the published origin, reachable by contributors; the one-line contrast with the already-correct upload path makes this a small, high-value fix).
2. **S2 — close the contributor `DELETE /api/store` gap** (total project destruction by a semi-trusted role; three-line fix mirroring the PUT guard).
3. **P1+P2+P3+P4 — do the actual npm packaging**: rename to guano, `bin` + `files` + `prepack` build so the tarball contains `dist/` and nothing private, data dir defaulting to cwd, LICENSE. Nothing about the planned distribution exists yet.
4. **C1 — fix the stale "Content"→"Preview" selector** so the only e2e test runs green on main; it currently masks regressions in exactly the flow (setup → edit → publish → view) a launch depends on, and it gates the CodeEditor split (Q4).
5. **C2–C6/Q5 — purge or rewrite the stale internal docs** (QUESTIONS.md, notes/, six referenced-but-missing files): they misstate the security posture in both directions and are currently on track to ship in the tarball.

## Verdict

The core product is in better shape than its paperwork: the build and type-check pass, the state model and DSL machinery are coherent, dead code is essentially zero, and the server shows real security craftsmanship (traversal-proof paths, origin-checked mutations, hashed secrets, an exporter whose HTML escaping survived a sink-by-sink audit with only two real gaps). But it is not launchable today on any of the three axes the launch depends on: security (one contributor-reachable stored XSS on the published origin and one project-destruction gap, both small fixes), distribution (the npm/CLI/scaffolder story is entirely unbuilt — the package is private, misnamed, ships secrets-adjacent local files, and omits the `dist/` it needs to run), and first-contact polish (boilerplate README, no LICENSE, "Vite App" title, a red e2e suite, and stale audit docs that describe fixed vulnerabilities as open). The encouraging part: S1, S2, and C1 are each sub-day fixes, and the packaging work is well-bounded because the server already resolves paths package-relatively. Realistic path to launch: one focused week — two days security + hygiene, three days packaging + scaffolder + docs — with the guano rename done as its own deliberate, compat-aware pass (Q3) rather than piecemeal.
